ID: T-012
Цель: Убрать хардкод `http://localhost:8000` из фронтенда, часть 1: общий конфиг и первые два файла.

Контекст:
- Во фронтенде базовый URL API захардкожен в нескольких файлах: `frontend/src/pages/LoginPage.tsx:10`, `RegistrationPage.tsx:9`, `SetupPage.tsx:11`, `GoogleCallback.tsx:10-18`, возможно в других.
- В контейнерах фронтенд и API работают с одного origin: запросы идут на `/api/...`, Nginx проксирует их на backend.
- Для разработки на хосте базовый URL переопределяется переменной `VITE_API_BASE_URL=http://localhost:8000` (CORS backend для `:5173` уже разрешён).

Файлы:
- создать: `frontend/src/config.ts`
- изменить: `frontend/src/pages/LoginPage.tsx`
- изменить: `frontend/src/pages/RegistrationPage.tsx`

Делать:
0. Выполнить `grep -rn "localhost:8000\|127.0.0.1:8000" frontend/src` и привести полный список файлов в начале ответа. Этой информации нет в recon.md.
1. `config.ts`: `export const API_BASE_URL: string = import.meta.env.VITE_API_BASE_URL ?? '/api';`
2. В `LoginPage.tsx` и `RegistrationPage.tsx` заменить локальную константу на импорт `API_BASE_URL`. Остальные файлы из списка не трогать, их возьмёт T-013.

Не трогать: остальные файлы фронтенда, `vite.config.ts`, логику запросов, backend.

Готово, когда:
- `cd frontend && npm run build` проходит без ошибок (`tsc -b && vite build`);
- в `LoginPage.tsx` и `RegistrationPage.tsx` нет `localhost:8000`;
- при `VITE_API_BASE_URL=http://localhost:8000 npm run dev` и запущенном backend логин и регистрация работают;
- в ответе есть полный список оставшихся файлов с хардкодом;
- дифф ≤3 файлов.

Как проверить: команды из «Готово»; в браузере открыть вкладку Network и убедиться, что запросы идут на `http://localhost:8000`.

Формат ответа: дифф + список оставшихся файлов с хардкодом.
