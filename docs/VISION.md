# VISION

## Что делаем
Курсовая по «Управление конфигурацией ПО», тема C: микросервисная архитектура на локальной машине.
Проект: **Chronella: контейнеризация веб-сервиса планирования учебной активности**.

Chronella (бакалаврская ВКР, защищена на 5): React + FastAPI + SQLite. Забирает расписание и рейтинг-план из ЭИОС МГУ им. Н.П. Огарёва, позволяет править события, экспортирует в Google Calendar, считает аналитику нагрузки.

**Предмет курсовой — развёртывание, не функционал.** Прикладная логика не меняется.

## Результат
Репозиторий, из которого на любой машине с Docker система запускается одной командой:
`docker compose up --build`

Состав:
- 3 контейнера: `frontend` (Nginx + React-статика), `backend` (FastAPI + Uvicorn), `db` (PostgreSQL 16)
- 2 Dockerfile (backend; frontend multi-stage)
- `docker-compose.yml`: закрытая сеть `chronella_net`, том `pgdata`, healthcheck БД
- конфигурация и секреты вне кода и вне образов (`.env`, `.env.example`)
- README с инструкцией запуска
- видео-демонстрация 10–12 минут

## Критерии успеха
1. `git clone` → заполнить `.env` → `docker compose up --build` → приложение работает на `http://localhost:8080` без ручной установки СУБД и зависимостей.
2. Снаружи доступен только порт Nginx (8080). `db` и `backend` с хоста недоступны.
3. Данные в PostgreSQL переживают `docker compose down` + `up` (без `-v`).
4. `backend` стартует только после успешного healthcheck `db`.
5. В образах и репозитории нет секретов.
6. Основные сценарии приложения работают: логин (JWT), подтяжка расписания из ЭИОС, правка события, экспорт в Google Calendar.
